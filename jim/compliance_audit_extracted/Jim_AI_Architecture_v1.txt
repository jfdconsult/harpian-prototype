10.1 Session Memory
Jim maintains conversational memory within a session (defined as a continuous browser session without logout). The last 6 conversation turns (user + Jim = 1 turn) are included in every request payload as conversation_history. Turns older than 6 are dropped from the context window (not from audit logs).
10.2 Cross-Session Continuity
Jim does not natively remember conversations from previous sessions. However, HARPIAN Core supports an optional Persistent Context Store — a structured summary of key points from prior Jim interactions with a user, stored in Core and injectable as context. This is available to Jim Institutional users only and must be explicitly enabled per organization.
10.3 Language Handling
Jim detects the language of the user's message and responds in the same language automatically. Both Brazilian Portuguese and English are fully supported. If the user switches language mid-session, Jim switches immediately. Mixed-language queries are answered in the dominant language of the query.

12.2 Regulatory Compliance Notes
Jim responses do not constitute investment advice under any regulatory framework. This is enforced via system prompt and must be reflected in UI documentation.
All Jim sessions are logged and retained for a minimum of 7 years (configurable per jurisdiction) in HARPIAN Core audit store.
Jim responses that reference specific portfolio actions include the disclaimer: "This is analytical context, not a regulated investment recommendation. Consult your suitability documentation before taking action."
Jim cannot be instructed by a user to remove, modify, or bypass compliance disclaimers.
In jurisdictions requiring AI disclosure: a persistent label "AI-powered — for informational use only" must be visible in the Jim chat UI at all times.
13.1 HAAL Service
FR-HAAL-01: HAAL must support Anthropic Claude, OpenAI GPT-4o, and Google Gemini as interchangeable providers via a unified internal interface.
FR-HAAL-02: HAAL must implement automatic failover: if primary provider returns error or times out after 5 seconds, HAAL retries with the next provider in the tier chain.
FR-HAAL-03: Provider API keys must never be included in any response or log accessible to the browser client.
FR-HAAL-04: HAAL must normalize all provider responses to a single internal response schema before returning to Core.
FR-HAAL-05: HAAL must implement output filtering: any response containing raw API keys, unexpanded template variables, or flagged harmful content must be suppressed and retried.
13.2 Context Assembly Engine (CAE)
FR-CAE-01: CAE must assemble the context payload fresh on every request. No cross-request caching of data components.
FR-CAE-02: CAE must enforce role-based data access rules independently of the browser client. FA tier must never receive client list data, AlphaDroid signals, or SGA status.
FR-CAE-03: CAE must enforce total context token ceiling of 4,200 tokens. If ceiling is exceeded, lower-priority data components must be trimmed (social signals first, then news, then DIME, then HPC detail).
FR-CAE-04: CAE must tag each context component with its data timestamp. Jim receives staleness information as part of context.
13.3 Jim Chat API Endpoint
FR-JIM-01: Endpoint: POST /v1/jim/chat — accepts user_message, session_id, conversation_history, client_id (optional), screen_context.
FR-JIM-02: Response: { message: string, session_id: string, turn_id: string, data_freshness: object, disclaimer_required: boolean }.
FR-JIM-03: Every response must include a disclaimer_required flag. If true, the client UI must render the appropriate compliance disclaimer below the response.
FR-JIM-04: Endpoint must validate JWT and extract role scope before invoking CAE. Unauthorized calls return 403 without invoking HAAL.
FR-JIM-05: Endpoint must write audit log entry on every call (success, error, or filtered response).
13.4 Jim UI Component (Browser)
FR-UI-01: Jim chat interface must be available as a modal overlay from any screen in Lite and Terminal.
FR-UI-02: Jim tier badge must be permanently visible in the chat header (Jim Lite / Jim Pro / Jim Institutional).
FR-UI-03: Contextual suggested prompts must update based on the screen the user is on when Jim is opened.
FR-UI-04: When disclaimer_required is true in the API response, display the appropriate disclaimer text below the Jim response in 12px gray text.
FR-UI-05: Jim input field must be disabled and show offline message when browser network is unavailable.
FR-UI-06: Rate limit state must be tracked client-side with server confirmation; display remaining message count when user is within 5 messages of limit.

What is NOT stored | Full conversation transcripts in persistent context (those exist only in audit logs)
Injection point | Prepended to Context Block as "Prior session notes:" before live data
Max size | 400 tokens — older items rolled off as newer items are added
User control | MFO admin can clear persistent context for any user via Terminal settings

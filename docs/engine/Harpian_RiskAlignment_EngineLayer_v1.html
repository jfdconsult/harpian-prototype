ENGINE 01Portfolio Risk Number — How RN Is Computed
Step 1 — Base Risk Score Per Position
RN_i = f( vol_i, liquidity_i, country_score_i, instrument_class_i )
→ Each position gets its own risk score (0–99) based on asset type, volatility, and jurisdiction
Step 2 — Weight-Adjusted Aggregation
RN_raw = Σ ( w_i × RN_i )
→ Simple weighted sum — linear component. Portfolio weight × position risk score, summed.
Step 3 — Structural Adjustments (Non-Linear Layer)
RN_portfolio = RN_raw
    + Δ_concentration    ← penalty: any single position >20%
    + Δ_correlation      ← penalty: assets move together in crisis
    − Δ_diversification  ← discount: uncorrelated buckets reduce total risk
    + Δ_liquidity       ← penalty: illiquid assets increase realized drawdown risk

Result: RN_portfolio ∈ [0, 99]
Concentration Penalty — Δ_concentration
· If max single position weight > 20% → add up to +8 pts
· If top-3 positions > 50% → add up to +5 pts
· Scales linearly with over-concentration severity
Correlation Penalty — Δ_correlation
· High avg pairwise correlation (>0.7) → add up to +10 pts
· "All positions move together in a crisis" = no real diversification
· Evaluated across 6-month trailing window
Diversification Discount — Δ_diversification
· Low average correlation (<0.3) across asset classes → subtract up to −8 pts
· Genuine geographic + asset class diversification rewarded
· Cannot reduce total RN below 60% of RN_raw
Liquidity Penalty — Δ_liquidity
· Assets with T+30 or longer settlement → add +3 pts per 10% allocation
· Private equity, real estate, locked structures → add +6 pts flat
· Because illiquid positions amplify drawdown in a forced sell scenario
ENGINE 02Blended Portfolio — Adding Core 11 & Core 22
New Portfolio Composition
New_Portfolio =
    ( 1 − X − Y )  ×  Current_Portfolio   ← existing holdings, compressed proportionally
    + X                 ×  Core_11              ← X = slider value, Core 11 product allocation
    + Y                 ×  Core_22              ← Y = slider value, Core 22 product allocation

Constraint: X + Y ≤ 1.0 | X ≥ 0 | Y ≥ 0
Blended RN — Linear Component
RN_blend_linear =
    ( 1 − X − Y ) × RN_portfolio
    + X              × RN_C11
    + Y              × RN_C22
→ Proportional weighted average. Foundation — then adjusted for non-linear effects below.
Blended RN — With Non-Linear Corrections
RN_blend = RN_blend_linear
    − Δ_corr_benefit    ← if C11/C22 has low correlation to existing portfolio: discount
    + Δ_vol_interaction ← if volatility regimes overlap: partial additive effect

Final: RN_blend ∈ [0, 99] — always within bounds
Correlation between Core 11 and typical LatAm/BRL portfolios is low by design. This means adding Core 11 tends to produce a diversification discount — blended RN drops more than simple weighting would suggest.

Correlation Rule
When two assets have correlation <0.3:
→ Combined volatility < weighted average volatility
→ Risk discount appears: total portfolio risk < sum of parts
σ_blend = √(w1²σ1² + w2²σ2² + 2·w1·w2·ρ·σ1·σ2)
Crisis Correlation Spike
In market stress events, correlations converge toward 1.0
→ Diversification discount disappears exactly when most needed
→ System uses stress-period correlation (not trailing normal) for drawdown estimation only
ρ_stress ≈ 0.75–0.95 for most equity-linked assets

Secondary Derived Metrics — How They're Computed
Blended Expected Return
R_blend = (1−X−Y)·R_portfolio + X·R_C11 + Y·R_C22
← Simple weighted average (returns are linear)
Blended Volatility (non-linear)
σ_blend = √( Σ w_i²·σ_i² + Σi≠j 2·w_i·w_j·ρ_ij·σ_i·σ_j )
← Full covariance matrix — inputs: 3 blocks (existing, C11, C22)
Expected Max Drawdown
DD_max ≈ σ_blend × k_stress
← k_stress uses stress-period correlation (ρ_stress ≈ 0.85)
← k varies by regime history of each product
Probability of Achieving Target
P_goal = Φ( ( R_blend·T − Gap ) / ( σ_blend·√T ) )
← Log-normal model. T = years. Φ = normal CDF.
← Gap = log(Target / Current_AUM)
All 4 formulas run sequentially in <10ms (pure arithmetic). Visual animation adds 100ms delay. Target: user perceives instant response — never sees calculation.

Recommendation Generation — Output Logic
Suggested % — How Computed
1. Solve for X, Y that minimizes gap to RN_appetite while maximizing P_goal
2. Subject to: X + Y ≤ MAX_harpian_%
3. Priority: C11 fills behavioral gap first. C22 fills return gap second.
4. Output: C11_suggested% + C22_suggested% + confidence band [min, optimal, max]
Confidence Band — What It Means
· Min: allocation that achieves alignment with P_goal ≥ 60%
· Optimal: allocation that maximizes P_goal within RN_appetite
· Max: allocation at RN_appetite ceiling (full tolerance usage)
· Band shown as shaded range on slider — user always sees where "optimal" is
ENGINE 07Goal + Time — How Horizon Changes Everything
Required Return — From Goal to RN
R_required = ( Target_AUM / Current_AUM )1/T − 1
← Geometric annual return needed to reach target in T years

RN_requirement = g( R_required, asset_class_universe )
← Maps required return to the minimum RN needed to plausibly achieve it
← Based on historical return/RN relationship of Harpian product universe
How T Affects All Outputs
↑ T (longer) → ↓ R_required → ↓ RN_requirement → ↑ P_goal
↓ T (shorter) → ↑ R_required → ↑ RN_requirement → ↓ P_goal

Key insight: the same portfolio can be "over-risked" at 3 years and "under-risked" at 15 years. RN_requirement is not fixed — it is a function of time.

ENGINE 09Numerical Simulations — 2 Concrete Examples
Simulation · 01
Conservative client (RN 30) / Portfolio too conservative (RN 20) / Moderate goal
Under-Risked
Given
RN_individual = 30  (behavioral ceiling)
RN_portfolio = 20  (current — very conservative)
RN_requirement = 32  (goal-based minimum)
RN_C11 = 42  |  RN_C22 = 58
Corr(portfolio, C11) ≈ 0.2 → diversification bonus active
Step-by-step
Scenario A: Add 25% Core 11
  RN_blend_linear = 0.75×20 + 0.25×42 = 25.5
  Corr discount (−2 pts) → RN_blend ≈ 23.5
  → Still below RN_requirement (32). Under-target.

Scenario B: Add 25% C11 + 15% C22
  RN_blend_linear = 0.60×20 + 0.25×42 + 0.15×58 = 31.7
  Corr discount (−1.5 pts) → RN_blend ≈ 30.2
  → Within 0.2 of RN_individual (30). Aligned
Verdict: Scenario B achieves alignment. Blended RN 30.2 just within behavioral ceiling. Return improves from 7% → 11.4% annualized. Drawdown goes from −10% to −12.8% (acceptable for this profile). P_goal rises from 38% → 71%.
Simulation · 02
Moderate client (RN 55) / Portfolio already at risk (RN 68) / Goal requires return
Over-Risked
Given
RN_individual = 55  (behavioral ceiling)
RN_portfolio = 68  (over behavioral limit by 13pts)
RN_requirement = 50  (goal-based minimum)
RN_C11 = 42  |  RN_C22 = 58
Key: adding Core 11 (RN 42) dilutes high-risk portfolio
Step-by-step
Scenario A: Add 40% Core 22 → wrong direction
  RN_blend = 0.60×68 + 0.40×58 = 63.8
  Still above RN_appetite (55). Worsens alignment

Scenario B: Add 35% Core 11 only
  RN_blend = 0.65×68 + 0.35×42 = 58.9
  Near ceiling. Corr discount (−2) → 56.9
  → Within 2 pts of appetite. Caution zone

Scenario C: 45% Core 11 (optimal)
  RN_blend = 0.55×68 + 0.45×42 = 56.3
  Corr discount → 54.2. Aligned
Verdict: Core 22 makes it worse (already over-risked). Core 11 is the right tool here — dilutes risk, improves alignment. At 45% Core 11: RN drops from 68 to 54.2. Return barely changes (−0.8%). Drawdown improves from −24% to −16%. P_goal improves from 61% to 77%.

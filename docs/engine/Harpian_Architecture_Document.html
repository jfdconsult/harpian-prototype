SECTION 01
System Overview
Harpian Intelligence Terminal is a B2B institutional platform serving Family Offices in Brazil and Latin America. It combines three distinct functions in one environment: risk diagnosis, allocation simulation, and recurring market intelligence.
Function 01
Risk Diagnosis
Onboard FO and clients. Collect risk questionnaires. Calculate Risk Numbers. Compare RN across FO / client / portfolio / requirement. Identify misalignment and classify zone.
Function 02
Allocation Simulation
Upload client portfolio. Parse asset weights. Simulate Core 11 + Core 22 allocation. Real-time recalculation of RN, return, drawdown, P(Goal). Enforce 10% max Harpian exposure.
Function 03
Market Intelligence
Institutional terminal with live ETP pricing, sector heatmaps, momentum rankings, StormGuard status, Don't Touch List, and tactical notes — creating daily usage habit.

SECTION 05
Main User Flows
Flow 1 — Family Office Onboarding
1
FO creates accountSets legal identity (name, CNPJ, regulator). Selects Harpian tier. Account activated.
2
FO completes institutional questionnaireDefines risk philosophy, mandate ceiling, investment stance. Outputs: RN_FO (institutional floor).
3
System sets max Harpian exposure = 10%This is a configurable constant (current default: 10%). All client simulations will be capped at this value.
4
FO accesses Overview DashboardEntry point to all modules. Can now onboard clients.
Flow 2 — Client Registration & Questionnaire
1
FO creates client recordEnters name, email, AUM, time horizon, target capital. Client appears in /clients with status "Pending Q".
2
System generates unique questionnaire linkLink is client-specific. Client accesses via email — no platform login required.
3
Client completes behavioral questionnaire20–30 scored questions covering loss aversion, time horizon sensitivity, volatility comfort, wealth dependency.
4
System calculates RN_Individual (0–99)Score stored. Client status updates to "Questionnaire Complete". FO notified. Client visible in /risk table.
Flow 3 — Portfolio Upload & RN Calculation
1
FO uploads portfolio fileAccepted: .xlsx, .pdf, .csv, .html. Drag-and-drop or file browser. Fallback: manual entry.
2
System parses portfolioExtracts: position names, weights (%), asset class, country, currency, instrument type. Infers liquidity bucket.
3
Engine calculates RN_PortfolioRN_portfolio = Σ(w_i × RN_i) + Δ_concentration + Δ_correlation − Δ_diversification + Δ_liquidity
4
Gap analysis runs automaticallySystem compares: RN_portfolio vs RN_individual, RN_individual vs RN_requirement, RN_portfolio vs RN_FO. Assigns zone.
Flow 4 — Allocation Simulation
1
FO opens Simulator for a clientFrom Client Detail CTA or sidebar. Simulator preloads client's RN data and current portfolio metrics.
2
FO drags Core 11 sliderSystem enforces: C11 % + C22 % ≤ 10% (FO mandate cap). Constraint bar updates. Sliders auto-lock at limit.
3
Real-time recalculation fires (<100ms)RN_blend, return, volatility, drawdown, P(Goal), time-to-target all update. Delta cards show marginal change.
4
Verdict box updates by zoneGreen (Optimal) / Amber (Limit) / Red (Still over-risked). Message includes specific number guidance.
5
FO applies strategy or exports proposal"Apply Allocation Strategy" confirms. "Export" generates PDF proposal. Allocation saved to client record.
Flow 5 — Intelligence Terminal (Daily Use)
1
FO opens terminal — /intelligenceFirst check: topbar SGA pill. If still Risk-On, proceed. If changed, navigate to /stormguard.
2
Reviews sector heatmap and momentum map12-cell heatmap shows daily sector performance. Momentum bars show 20-day relative strength per sector.
3
Checks Don't Touch List7+ ETFs and 5 equities with weak momentum. Reviews if any client portfolios have exposure to flagged assets.
4
Reads weekly tactical noteHarpian-authored market summary. Context for client conversations. No explicit position disclosure.

SECTION 07
Calculation Logic
Risk Number — Portfolio (3-Step Engine)
// STEP 1: Base weighted sum RN_raw = Σ ( weight_i × RN_i ) // weight_i = position allocation %, RN_i = per-asset risk score (0–99) // STEP 2: Structural adjustments (non-linear) Δ_concentration = f(max_single_weight, top3_weight) // if max position > 20%: +up to 8pts | if top-3 > 50%: +up to 5pts Δ_correlation = f(avg_pairwise_corr_trailing_6m) // if avg_corr > 0.7: +up to 10pts | crisis regime uses ρ_stress ≈ 0.85 Δ_diversification = f(avg_cross_asset_corr) // if avg_corr < 0.3: -up to 8pts | floor: cannot reduce below 60% of RN_raw Δ_liquidity = f(illiquid_weight) // T+30 assets: +3pts per 10% | locked structures: +6pts flat // STEP 3: Final score RN_portfolio = RN_raw + Δ_concentration + Δ_correlation − Δ_diversification + Δ_liquidity // Result: RN_portfolio ∈ [0, 99]
Blended RN — With Harpian Allocation
// Weights w_exist = (100 - c11_pct - c22_pct) / 100 w_c11 = c11_pct / 100 w_c22 = c22_pct / 100 // Constraint: w_exist + w_c11 + w_c22 = 1.0 // Linear blend RN_blend_linear = w_exist × RN_portfolio + w_c11 × RN_C11 + w_c22 × RN_C22 // RN_C11 = 42 (fixed) | RN_C22 = 58 (fixed) // Correlation correction corr_discount = (c11_pct + c22_pct) × 0.15 // approx. — low corr to LatAm mix RN_blend = max(RN_blend_linear - corr_discount, 10)
Secondary Metrics — Simulator Outputs
// Expected return (linear) R_blend = w_exist × R_portfolio + w_c11 × R_C11 + w_c22 × R_C22 // Blended volatility (non-linear — 3-block covariance) σ_blend = √(Σ w_i² × σ_i² + Σ_{i≠j} 2 × w_i × w_j × ρ_ij × σ_i × σ_j) // Expected max drawdown (stress-corrected) DD_max ≈ σ_blend × k_stress // k_stress derived from product regime history // Probability of achieving goal (log-normal model) Gap = log(target_aum / current_aum) P_goal = Φ( (R_blend × T − Gap) / (σ_blend × √T) ) // Φ = normal CDF | T = time_horizon_years // Risk Budget accounting Risk_Budget = min(RN_individual, RN_capacity) Risk_Used = RN_blend Risk_Available = Risk_Budget − Risk_Used
Constraint Enforcement — 10% Cap
// Hard constraint — enforced in slider JS and backend validation MAX_harpian_pct = FamilyOffice.max_harpian_pct // default: 10 IF (c11_pct + c22_pct) > MAX_harpian_pct: // Auto-reduce last-moved slider to enforce cap IF active_slider == 'c11': c11_pct = MAX_harpian_pct - c22_pct ELSE: c22_pct = MAX_harpian_pct - c11_pct // Additional hard stops (block UI and API) IF RN_blend > RN_FO: → "FO mandate breach" — hard block IF Risk_Available < 0: → "Budget overdrawn" — reduction mode only

SECTION 08
Intelligence Layer
⚠ Intelligence layer is informational only. It does not expose Harpian's internal positions. Its purpose is to deliver institutional authority and daily utility, not to replicate the full strategy.
StormGuard Armor (SGA)
What Is Shown
  • Current SGA status: RISK-ON / NEGATIVE / DEFENSIVE
  • Signal value (±numeric)
  • Days in current regime
  • Core 11 position % (0 = cash, 100 = invested)
  • Historical event log with dates and outcomes
  • 3-step protocol explanation (signal → Day 0 → Day 1)
What Is NOT Shown
  • SGA formula internals
  • Which assets are currently held
  • Next expected signal direction
  • Full AlphaDroid model output
SGA state drives the topbar pill color (green = Risk-On / red = Defensive) and the stormguard mini widget on the Overview dashboard. State is fetched from API on page load and auto-refreshes every 60 seconds.
Don't Touch List (DTL)
AspectSpecification
ContentETFs and individual equities with below-threshold momentum scores in the Harpian universe
MethodologySignal-to-noise ratio filtering. Assets stretched excessively above mean or with weak relative momentum relative to investable universe
What it showsTicker · Full name · Sector · Momentum score (0–99) · Classification (Weak / Caution / Avoid)
What it does NOT showPosition sizing, current holdings, full ranking methodology, strategy decisions
Update cadenceDaily refresh · Timestamp always visible
DisclaimerInformational only — not investment advice. Presence on list ≠ "will fall"

// useSimulator.ts — core calculation hook const RN_C11 = 42, RN_C22 = 58 // fixed product values function calculateBlend(c11: number, c22: number, client: Client) { const combined = c11 + c22 if (combined > client.fo.max_harpian_pct) throw Error("Cap exceeded") const w_exist = (100 - combined) / 100 const rn_linear = w_exist * client.rn_portfolio + (c11/100) * RN_C11 + (c22/100) * RN_C22 const corr_discount = combined * 0.15 const rn_blend = Math.max(rn_linear - corr_discount, 10) const r_blend = w_exist * client.expected_return + (c11/100) * R_C11 + (c22/100) * R_C22 const vol_blend = calculateVolatility(w_exist, c11/100, c22/100, client) const dd_max = vol_blend * K_STRESS const gap = Math.log(client.target_aum / client.current_aum) const p_goal = normalCDF((r_blend * client.horizon - gap) / (vol_blend * Math.sqrt(client.horizon))) return { rn_blend, r_blend, vol_blend, dd_max, p_goal, zone: classifyZone(rn_blend, client) } } // Fires on every slider input event — must complete in <10ms

SECTION 12
Development Notes & Critical Points
Performance — Simulator
⚡ CRITICAL: Simulator recalculation must complete in <10ms from slider input. All math runs in frontend. Backend is only called to PERSIST confirmed scenarios — never for live calculation. Delay = broken UX.
  • All calculation logic lives in lib/calculations.ts — pure functions, no async, no API calls
  • Slider event fires oninput, not onchange — continuous feedback
  • Animate metric values with CSS transitions (transition: width 0.3s on bars)
  • Hexagon SVG path morphs with transition: all 0.3s ease on the polygon points
  • Delta cards update instantly — no animation delay
Constraint Enforcement — 10% Cap
⚠ The 10% cap on combined Harpian exposure is a HARD CONSTRAINT at both frontend and backend level. It is not a soft warning — it is a hard lock. Violation must be impossible, not just discouraged.
  • Frontend: slider auto-reduces when cap is hit (existing JS logic in Simulator HTML)
  • Backend: POST /simulate and POST /allocation/apply must validate and reject if c11+c22 > max_harpian_pct
  • max_harpian_pct comes from the FamilyOffice record, not a constant
  • FO Admin can change this value in Settings — must immediately affect all active simulators
  • Constraint bar visual changes color: green → amber (70%) → red (90%+)

Security & Permissions
  • Questionnaire link uses a single-use token — expires after completion or 72h
  • Client (external) has NO access to the terminal — questionnaire is a completely separate surface
  • All API endpoints require authenticated FO session (JWT or session cookie)
  • Read-Only users: block all POST/PUT endpoints at middleware level
  • Intelligence data endpoints (DTL, sector momentum, SGA): no PII, safe to cache at CDN layer
State Management
  • Simulator state is local component state — never persisted until "Apply" is clicked
  • Active client context (which client is being viewed) lives in React context or URL param
  • SGA status and prices live in a global polling store (Zustand or React Query)
  • FO config (max_harpian_pct, RN_FO) fetched once at login and cached in context
Portfolio File Parsing
  • Parsing runs server-side — uploaded files never touch the frontend calculations
  • Expected columns: position name, allocation %, asset class (or auto-classify by ticker)
  • Country and currency are inferred from ticker where possible; manual override allowed
  • Liquidity bucket: default T+2 for ETFs, T+0 for cash, custom for PE / real estate
  • For positions unrecognized by the system: prompt FO to classify manually before RN calc
  • Maximum 500 positions — above this, show warning and request aggregation
Scalability Notes
  • Each FO is isolated — multi-tenancy at the data level (FO ID on every record)
  • Intelligence data is shared across all FOs — single feed, no per-FO computation needed
  • Simulator runs entirely client-side — no scaling concern for real-time recalculation
  • PDF report generation should be async — queue job, return URL when ready
  • Portfolio uploads should be processed asynchronously — show "Parsing..." state during processing
  • SGA signal webhook: Harpian backend pushes SGA changes → frontend subscribes via WebSocket or SSE
